> 版本：Final 2.0  
> 日期：2026-10-30  
> 调研对象：项目发起人（单用户）  
> 文档边界：只记录调研证据、事实、痛点、需求表达和研究洞察，不确认产品功能、MVP或技术方案。

## 1. 调研摘要

调研对象为研究生用户，主要学习数理统计、金融、Python、R 和 SQL，典型学习任务包括课程学习、作业、考试和课程 Project。主要资料为 syllabus、教材和课件 PDF，目前主要使用 GPT 辅助梳理知识点和讲解题目。

用户的核心目标不是更快生成摘要，而是**真正理解并掌握一门课程**。用户需要先看清课程的完整逻辑，再理解每个定义、定理、公式和方法，最后通过与真实作业和考试相近的练习验证能否独立应用。

核心问题是：

> 面对包含大量定义、公式、章节依赖和客观题考核的课程，用户难以将分散资料转化为清晰的知识体系，也难以持续判断自己是否真正理解并能解决新问题。

## 2. 调研目标与范围

### 2.1 目标

- 理解用户真实的学习流程、目标、痛点与约束；
- 了解同类已上线产品和开源项目解决问题的方式；
- 识别尚未被充分满足的学习需求；
- 为后续需求分析与立项提供事实依据。

### 2.2 范围

- 只对项目发起人进行用户研究；
- 按项目要求默认市场需求存在且规模较大；
- 不开展额外问卷、访谈或市场规模测算；
- 竞品研究覆盖公开网站、App介绍页和 GitHub 项目；
- 本文不确认优先级、MVP、产品架构或技术选型。

### 2.3 方法

1. 已上线产品桌面研究；
2. GitHub 开源项目研究；
3. 28 个问题的结构化单用户访谈；
4. 用户任务、痛点、需求和机会归纳；
5. 竞品发现与用户回答交叉验证。

### 2.4 局限

- 样本为单用户，结论不代表全部学生；
- 部分竞品未进入登录或付费后的完整流程；
- 尚未使用真实 syllabus、课件和作业验证解析效果；
- 尚未确认首门课程、文件规模、价格范围和数据保存期限。

## 4. 用户学习观念

用户认为“理解”是学习的中心。真正理解一个知识点，需要能够回答：

- 定义为什么这样构造？
- 公式中每个部分是什么意思？
- 它解决什么问题？
- 能否通过例子和反例说明？
- 实际应用场景是什么？
- 做题时如何判断应该使用它？
- 是否存在标准的解题过程？
- 换一道新题后能否独立应用？

因此，单纯摘要、记忆定义或机械完成原题不能满足用户对“学会”的判断。

## 5. 当前学习流程

1. 获取 syllabus、教材、课件、作业和 Mock Exam；
2. 尝试梳理课程知识框架和每章的意义；
3. 学习定义、公式及相关知识；
4. 使用 GPT 补充解释或讲解题目；
5. 完成作业、练习和模拟考试；
6. 通过做题加深理解和记忆；
7. 通过复述、独立解题和解决新题判断掌握程度。

GPT 当前主要帮助用户：

- 快速梳理课件内容；
- 提取定义和公式；
- 对定义、公式进行拓展解释；
- 讲解题目和解题思路。

## 6. 用户痛点

| 痛点 | 用户证据 | 影响 |
|---|---|---|
| 缺少课程全景 | 希望先获得课程 Roadmap 和完整框架 | 不知道章节意义、关系和学习顺序 |
| 没有稳定计划 | 用户通常不制定计划，希望 AI 帮助安排并调整 | 学习节奏不稳定 |
| 从零开始困难 | 复杂定义和公式不理解 | 启动成本高、容易拖延 |
| 理论与做题脱节 | 定义学明白后仍不知道如何应用 | 难以形成迁移能力 |
| 解释未击中认知缺口 | GPT 有时不能判断用户具体哪里不懂 | 需要反复追问，仍可能没有理解 |
| 缺少掌握验证 | 用户需要复述、做题和新题验证 | 看完不等于学会 |
| 缺少薄弱项闭环 | 希望自动识别并强化薄弱项 | 错误可能反复出现 |
| 时间信息分散 | 课程、作业、项目和考试 DDL 分散 | 难以安排学习和冲刺 |
| 错误知识不可接受 | 用户明确表示错误知识会导致停止使用 | 直接破坏产品信任 |
| 数据隔离要求严格 | 用户要求每人独立数据库，不得与其他用户共享 | 数据与隐私是使用前提 |

## 7. 核心用户任务（JTBD）

> 当我开始学习一门包含大量定义、公式和练习的课程时，我希望 AI 能从 syllabus、教材、课件和作业中梳理出完整、正确的知识体系，帮助我逐步理解各知识点，并用贴近课程考核的练习持续验证，使我最终能够独立完成作业和解决新题。

### 7.1 功能性任务

- 看清课程范围、章节关系和时间安排；
- 知道当前和下一步应该学习什么；
- 理解定义、定理、公式和方法；
- 将抽象知识连接到例子、应用和题目；
- 获得可重复执行的解题或编程步骤；
- 通过定义和公式抽查确认记忆；
- 通过多道相似题降低蒙对的可能；
- 通过新题确认迁移能力；
- 识别薄弱项并重新学习；
- 根据实际进度调整安排；
- 在考试前集中复习高价值内容。

### 7.2 情绪性任务

- 降低从零开始学习复杂课程的压力；
- 减少“不知道是否真正学会”的不确定感；
- 获得对课程结构和当前进度的掌控感；
- 避免因概念难懂和计划缺失而拖延或放弃。

## 8. 用户需求证据

### 8.1 课程结构与时间线

用户希望上传 syllabus、教材和全部课件后，得到按“课程—大章节—小章节—知识点”组织的逻辑框架，同时识别课程安排、作业、Project、考试及 DDL。

### 8.2 深度理解

用户需要围绕知识点获得原始定义、通俗解释、构造原因、公式含义、例子、应用场景、前后关系、解题信号和标准步骤。不同教学方法应交替使用，直到定位并解决具体认知障碍。

### 8.3 贴近真实考核的练习

用户希望系统理解上传作业题考查的知识点、题型和出题方式，再生成相近但不相同的题目用于讲解和考察。如果资料中没有对应题目，可以生成原创练习。

用户希望一个知识点结束后进行抽查，并通过多道题降低偶然答对的影响。上传的作业原题可以保留为后续验证材料，用于再次判断是否真正掌握。

### 8.4 学情与复习

用户希望系统根据作答结果识别未掌握或反复出错的知识点，并安排重新学习、强化练习、间隔复习和考试冲刺。

### 8.5 动态安排与人工控制

用户希望 AI 主动推荐任务、调整计划和提醒，同时允许手动跳过当天、增加任务或选择重学某个章节。

### 8.6 正确性与数据隐私

用户无法接受错误知识，愿意上传真实资料的前提是建立严格隔离的个人数据空间，不能与其他用户共享。

## 9. 用户成功标准

用户认为产品有效需要满足：

- 能够复现课程完整知识框架；
- 能正确识别课程安排和 DDL；
- 用户能够自主梳理和复述知识结构；
- 定义和公式抽查能够通过；
- 能完成与课程作业相近的新题；
- 能完成保留的真实课程题目；
- 能解决此前未见过的新题；
- 能明确指出未掌握的知识点并帮助重新学习。

开源项目普遍存在的问题：

- 强调多 Agent，但缺少与确定性工作流的对比；
- Demo 数据较少，不能证明真实课程效果；
- 中文 PDF、扫描件、公式和复杂表格支持不足；
- 主观或复杂题目批改缺少可靠标准；
- 长期记忆可能只是历史文本，不等于可解释学情；
- 很少证明使用后学习效果真正提升。

## 12. 关键研究洞察

### 洞察 1：用户购买的是理解与掌握，而不是内容生成

用户已经能使用 GPT 快速生成总结。产品必须更了解课程结构和用户认知缺口，并通过练习证明掌握。

### 洞察 2：知识地图可能是整个学习闭环的核心对象

知识地图既是课程入口，也可以连接来源、章节依赖、学习状态、题目、错因和复习安排。

### 洞察 3：讲解的重点是“为什么”和“如何应用”

用户困难不在于缺少定义，而在于不知道定义为什么成立、何时使用、如何转换成解题步骤。

### 洞察 4：掌握验证需要覆盖记忆、理解和迁移

定义抽查只能验证记忆；相似题可以验证方法使用；保留题和新题才能进一步验证迁移。

### 洞察 5：作业是课程考核方式的重要证据

作业不只是待完成任务，还能反映老师强调的知识点、题型和难度。它可以帮助建立更贴近真实课程的练习方式。

### 洞察 6：AI主动性必须与用户控制共存

用户希望 AI 主动安排，但也要求跳过、增加和重学。因此系统不能不可解释地替用户决定。

### 洞察 7：正确性和数据隔离是准入门槛

错误知识会造成直接流失，跨用户使用资料会破坏信任。这两项必须在后续方案中优先验证。

## 13. 问题定义

研究生课程资料分散、概念抽象、知识依赖复杂，现有通用 AI 工具虽然能回答单个问题，却无法稳定建立课程全景、持续识别个人认知缺口，也无法用贴近真实考核的练习证明掌握。

本项目需要进一步分析的价值机会是：

> 基于用户真实课程资料，将课程重建为可导航的知识体系，并围绕用户是否真正理解和能够迁移应用，持续组织讲解、练习、复习和考试准备。

## 14. 调研结论

本次调研支持进入需求分析与立项阶段。

研究已经确认：

- 用户存在真实、持续且明确的学习问题；
- 课程知识地图和深度理解是核心诉求；
- 贴近作业模式的练习是验证理解的重要手段；
- 用户愿意上传真实资料和完成初始诊断；
- 产品必须控制错误知识并严格隔离数据；
- 市场同类产品证明该产品形态可成立，但仍有整合课程地图、理解、验证和动态学习闭环的差异化空间。

本文件不确定具体功能、优先级和技术实现，相关内容进入独立的《需求分析与立项终版》。

## 2026-10-31 调研后的用户反馈记录

本节是调研完成后、用户试用 MVP 时提出的新增反馈，保留原调研结论，不将其伪装成最初访谈结果。

- 用户要求按 Canvas 式层级组织 Dashboard、课程内部板块、Timeline 和 Settings；知识地图节点应能进入定义、公式、应用与来源的详情。
- 用户确认六门课程采用不同主题色，Timeline 只显示考试与 Project，不展示普通上课日期。
- 用户要求设置项与实际行为联动，包括提醒、AI 讲解、每日模型调用上限及中英文界面切换。
- 用户重申 syllabus、课件、作业和可合法获取的教材资料应共同支持课程内容；教材书目信息不能替代教材正文，所有课程的内容与仿题质量仍需核验。

这些反馈已进入需求分析、产品方案和 PRD 的 2026-10-31 执行附注。当前实现状态和未完成项以 34 号项目日志、35 号版本日志为准。
