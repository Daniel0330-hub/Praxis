# 个性化学习 Agent｜产品方案设计 v0.1

> 项目暂定名：Praxis知行伴学 / EduAgent CN  
> 版本：0.1（评审稿）  
> 日期：2026-10-30  
> 输入：《需求调研终版》《需求分析与立项终版》  
> 文档边界：确定产品结构、流程、功能、交互和异常处理；不确定模型、框架、数据库和具体技术实现。

## 1. 产品定义

### 1.1 一句话定义

Praxis知行伴学是一款基于用户真实课程资料的个性化学习 Agent：它将 syllabus、课件、教材和作业重建为可学习的课程知识地图，通过可信讲解和贴近课程考核的练习，帮助用户真正理解并验证掌握。

### 1.2 核心用户

首个用户为使用电脑学习数理统计、金融、Python、R、SQL 等课程的研究生。首版聚焦单用户、单课程、PDF和客观题。

### 1.3 核心价值

产品依次解决四个问题：

1. **学什么**：从真实课程资料中建立课程全景和学习顺序；
2. **怎么理解**：围绕为什么、怎么用和如何做题进行结构化讲解；
3. **是否掌握**：通过多道相似题和保留题验证；
4. **哪里需要重学**：根据答题证据定位薄弱点并重新教学。

### 1.4 产品承诺

- 课程事实尽量有来源；
- AI生成内容与资料原文明确区分；
- 掌握状态必须展示判断依据；
- 用户可以修改课程结构、拒绝AI建议并重新测试；
- 用户资料和学习记录不与其他用户混用。

### 1.5 产品不承诺

- 不保证替代教师或学校正式评分；
- 不自动完成或提交作业；
- 不把一次答对视为掌握；
- 不在证据不足时假装确定；
- 不在首版覆盖全部题型和文件格式。

## 2. 产品设计原则

### 2.1 理解优先

所有内容和交互围绕用户能否解释、应用和迁移知识，而不是生成更多资料。

### 2.2 课程证据优先

优先依据用户上传的课程资料。通用补充知识必须标记为“扩展解释”，不能冒充教材或老师观点。

### 2.3 地图驱动

课程知识地图是核心导航和状态载体。资料、讲解、题目、错因和掌握度都应回到具体知识点。

### 2.4 教学与验证分离

用于讲解和出题参考的内容不能污染最终验证集。产品需要让用户清楚知道当前处于学习、练习还是验证阶段。

### 2.5 AI主动、用户可控

AI可以决定是否继续讲解、提问或练习，但必须说明原因，并允许用户切换、跳过、重学或手动进入测试。

### 2.6 错误可发现、可修正

用户必须能够查看来源、报告错误、修正课程结构，并触发相关内容重新生成。

### 2.7 渐进式复杂度

首次进入先展示课程全景和下一步，不一次暴露所有高级功能。

## 3. 产品架构

### 3.1 核心对象

| 对象 | 说明 |
|---|---|
| 用户 | 资料、课程、记录和记忆的归属主体 |
| 课程 | 一组 syllabus、课件、教材、作业及其学习状态 |
| 资料 | 用户上传的 PDF及其用途、解析状态和来源信息 |
| 课程事件 | 作业、Project、考试、课程安排和 DDL |
| 知识节点 | 课程、大章节、小章节、知识点 |

| 学习单元 | 围绕单一知识点的一次讲解与练习过程 |
| 题目 | 教学示例、出题参考、练习或最终验证题 |
| 作答 | 用户答案、提示使用、结果、错因和证据 |
| 掌握状态 | 未开始、学习中、待验证、已掌握、需复习 |

## 4. 核心业务流程

### 4.1 课程初始化流程

```text
创建课程
→ 上传 syllabus / 课件 / 教材 / 作业
→ 系统识别文件用途
→ 用户确认或调整用途
→ 解析课程结构、知识点、事件和题目
→ 生成课程知识地图与时间线草稿
→ 用户审核与修改
→ 确认课程初始化
→ 进入课程总览
```

关键原则：AI生成的课程结构必须先经过用户确认，不能直接成为不可修改的最终结构。

### 4.2 知识点学习流程

```text
选择知识点
→ 查看学习目标和前置知识
→ 初始诊断
→ 结构化讲解
→ AI判断当前状态
   ├── 仍不理解：切换解释方式
   ├── 基本理解：进入例子/应用
   └── 可以验证：进入练习
→ 用户也可随时选择继续讲、给例子或开始做题
```

### 4.3 作业驱动练习流程

```text
确定目标知识点
→ 查询是否存在对应作业题型
   ├── 有：分析考点、题型、难度和表达方式
   └── 无：使用课程资料生成原创题
→ 生成多道不重复练习
→ 用户逐题作答
→ 批改并定位错因
→ 判断是否需要重新讲解
→ 达到练习准入条件
→ 进入最终验证
```

### 4.4 最终验证流程

```text
练习阶段通过
→ 调取未用于教学或生成的保留题
→ 无提示独立作答
→ 结果评估
   ├── 通过：标记已掌握
   ├── 临界：补充一道迁移题
   └── 未通过：回到对应薄弱环节
→ 展示掌握判断依据
```

### 4.5 重新学习流程

```text
发现薄弱知识点
→ 展示错误类型和历史证据
→ 用户选择重学或AI建议重学
→ 从最小必要前置知识开始
→ 使用不同讲解方式
→ 新一轮练习
→ 重新验证
```

## 5. 页面与功能设计

### 5.1 页面 P01：课程中心

**目标**：快速进入已有课程或创建新课程。

**主要内容**：

- 课程卡片：课程名、资料数量、知识点进度、最近学习、下一项；
- 创建课程入口；
- 最近学习记录；
- 异常提示：资料解析失败、课程等待确认等。

**主要操作**：

- 创建课程；
- 继续学习；
- 查看课程；
- 进入课程设置。

### 5.2 页面 P02：创建课程向导

分为四步：

1. **基本信息**：课程名、课程方向、考试日期、每周可用时间；
2. **上传资料**：拖拽或选择 PDF；
3. **资料用途确认**：syllabus、课件、教材、作业、答案/评分规则；
4. **处理与预览**：显示解析进度、问题和初步识别结果。

**关键交互**：

- 自动识别用途，但用户必须可修改；
- 上传答案时提示其不得进入练习生成和最终验证上下文；
- 对扫描件、加密文件、超大文件或无文本文件即时提示；
- 支持稍后补充资料。

### 5.3 页面 P03：课程初始化审核

**目标**：在学习开始前确认AI理解的课程是否正确。

采用左右分栏：

- 左侧：课程知识树；
- 右侧：当前节点详情、来源、课程事件和关联资料。

用户可以：

- 修改章节或知识点名称；
- 调整层级；
- 合并或拆分节点；
- 删除错误节点；
- 标记遗漏；
- 修改 DDL；
- 查看每个节点的来源；
- 重新解析指定文件。

确认后进入课程总览。后续仍允许修改，但需提示可能影响既有题目与学情。

### 5.4 页面 P04：课程总览

**目标**：回答“这门课是什么、我在哪里、下一步做什么”。

**模块**：

- 课程概览：章节数、知识点数、资料数；
- 掌握概览：未开始、学习中、待验证、已掌握、需复习；
- 下一步建议：推荐学习的知识点及原因；
- 知识地图缩略图；
- 课程时间线：最近作业、Project、考试；
- 最近学习与薄弱项；
- 继续学习按钮。

### 5.5 页面 P05：知识地图

提供两种视图：

1. **树形视图**：课程—大章节—小章节—知识点；
2. **关系视图**：展示关键前置、应用和对比关系。

首版默认树形视图，关系视图仅展示核心关系，避免过度复杂。

每个节点显示：

- 名称和知识类型；
- 掌握状态；
- 来源数量；
- 是否有作业题型；
- 是否存在未解决问题；
- 下一步建议。

### 5.6 页面 P06：知识点学习工作台

采用三栏结构：

- 左栏：章节目录和学习状态；
- 中栏：讲解、对话、例子和练习主区域；
- 右栏：来源、学习目标、掌握依据和操作。

**知识点头部**：

- 知识点名称；
- 所属章节；
- 知识类型；
- 前置知识；
- 当前状态；
- 学习目标。

**讲解卡片结构**：

1. 原始定义/公式；
2. 一句话直觉；
3. 为什么这样定义；
4. 符号或组成部分；
5. 例子和反例；
6. 应用场景；
7. 做题识别信号；
8. 标准步骤；
9. 常见错误；
10. 来源。

用户快捷操作：

- “换一种方式解释”；
- “给我一个例子”；
- “我不理解这一步”；
- “用题目讲解”；
- “开始测试”；
- “查看原文”。

### 5.7 页面 P07：练习模式

**练习前**显示：

- 目标知识点；
- 练习目的；
- 题目数量；
- 题型和预估难度；
- 是否参考课程作业风格。

**答题中**：

- 一次只呈现一题；
- 用户提交后再显示反馈；
- 提示分为一级提示、二级提示和完整讲解；
- 记录是否使用提示；
- 允许“这道题有问题”反馈。

**答题后**：

- 正误；
- 正确答案；
- 解题过程；
- 使用知识；
- 错误类型；
- 来源；
- 下一步建议。

### 5.8 页面 P08：最终验证模式

与练习模式视觉上明显区分，强调：

- 当前为独立验证；
- 不提供答案和逐步提示；
- 题目未用于前面的讲解和练习；
- 完成后统一显示结果。

验证结束展示：

- 是否通过；
- 使用的验证证据；
- 错误知识点；
- 掌握状态变化；
- 继续学习、重学或补充验证入口。

### 5.9 页面 P09：学情中心

**模块**：

- 课程掌握分布；
- 薄弱知识点；
- 重复错误；
- 最近练习和验证记录；
- 每个掌握状态的证据；
- 重新学习入口。

首版不设计复杂积分或排行榜。

### 5.10 页面 P10：资料与数据管理

- 文件列表及用途；
- 解析状态和错误；
- 知识节点关联数量；
- 重新解析；
- 替换文件；
- 删除文件及影响提示；
- 删除课程；
- 数据隔离和使用说明。

## 6. Agent教学决策设计

### 6.1 Agent可以主动决定

- 是否先检查前置知识；
- 是否需要换一种解释方式；
- 是否用例子或题目辅助理解；
- 是否进入小测；
- 练习题数量是否需要增加；
- 是否建议重新学习；
- 是否已经满足最终验证的准入条件。

### 6.2 Agent决策依据

- 用户最近回答；
- 是否使用提示；
- 错误类型；
- 同一知识点历史表现；
- 前置知识状态；
- 题目难度；
- 是否能解释思路；
- 当前资料证据是否充分。

### 6.3 Agent必须说明

每次关键切换给出简短原因，例如：

- “你能复述定义，但在判断使用条件时出错，我建议先做一个反例。”
- “连续两道基础题正确，可以进入应用题。”
- “这道题使用了提示，暂不作为独立掌握证据。”
- “课程资料中没有足够证据，我无法确定老师采用哪种定义。”

### 6.4 用户始终保留的控制

- 继续讲解；
- 跳过讲解；
- 指定教学方式；
- 手动开始练习；
- 增加题目；
- 退出验证；
- 标记题目错误；
- 重学知识点；
- 修改课程结构。

## 7. 掌握状态设计

### 7.1 状态定义

| 状态 | 含义 | 进入条件方向 |
|---|---|---|
| 未开始 | 尚未进行有效学习 | 默认状态 |
| 学习中 | 已开始讲解或诊断 | 产生学习行为 |
| 待验证 | 练习表现达到验证准入 | 多题表现基本稳定 |
| 已掌握 | 独立通过最终验证 | 保留题或迁移题通过 |
| 需复习 | 曾掌握但表现下降，或验证未通过 | 新错误、重复错误或时间衰减 |

### 7.2 状态证据

状态详情至少显示：

- 最近一次评估时间；
- 题目数量和难度；
- 正确率；
- 是否使用提示；
- 最终验证结果；
- 主要错因；
- 状态变化原因。

用户可以发起重新测试，但不能直接手动把知识点标记为“已掌握”。用户可以将AI判断标记为“不准确”，进入复核状态。

## 8. 题目生命周期设计

### 8.1 题目角色

| 角色 | 用途 | 用户是否可提前看到 |
|---|---|---|
| 教学示例 | 配合讲解展示方法 | 可以 |
| 出题参考 | 识别课程考法和难度 | 不直接展示答案 |
| AI练习 | 练习和诊断 | 做题时展示 |
| 最终验证 | 独立判断掌握 | 验证开始后展示 |

### 8.2 用户配置

上传作业时，系统先建议用途，用户可以调整：

- “可用于讲解”；
- “仅用于参考出题”；
- “保留用于最终验证”。

如果保留题数量不足，系统提示用户：

> 当前没有足够的独立验证题。可以由AI生成迁移题，但验证可信度会降低。

### 8.3 防复制交互

生成练习时不展示参考原题。若AI题目与原题高度相似，系统自动换题。用户可举报“与原题过于相似”。

## 9. 关键交互规则

### 9.1 来源展示

- 定义、公式和课程事实旁显示来源标记；
- 点击来源打开右侧原文片段；
- 显示文件名和页码；
- 多来源冲突时并列展示并提示用户确认；
- 扩展知识使用不同标签。

### 9.2 AI内容标识

- 资料原文：标记“课程资料”；
- AI解释：标记“AI解释”；
- AI生成题：标记“AI生成”；
- 最终验证题：标记“独立验证”；
- 用户修改：标记“用户已校正”。

### 9.3 保存与恢复

- 学习工作台自动保存；
- 用户退出后可从上次位置继续；
- 解析或生成中断后保留已完成结果；
- 失败操作允许单步重试，不要求重做整门课程。

### 9.4 高风险确认

以下操作需要二次确认并显示影响范围：

- 删除资料；
- 删除课程；
- 重新解析并覆盖知识地图；
- 修改已学习知识点的层级；
- 将已使用题目改为最终验证题。

## 10. 异常与兜底体验

| 异常 | 用户提示 | 产品处理 |
|---|---|---|
| PDF无法读取 | 无法识别文本，可能是扫描件或加密文件 | 标记失败文件，其他文件继续处理 |
| 公式解析不确定 | 公式可能有误，请核对原文 | 展示原图/原文并允许校正 |
| 章节结构冲突 | 多份资料对章节划分不同 | 展示两个候选结构，由用户选择 |
| DDL冲突 | syllabus与课件日期不同 | 并列来源，不自动覆盖 |
| 找不到知识点证据 | 课程资料中未找到可靠依据 | 拒绝伪造，允许用户补充资料 |
| 生成题无解或多解 | 题目质量检查未通过 | 自动废弃并换题 |
| 用户认为批改错误 | 提供申诉入口 | 重新检查并保留争议记录 |
| 无对应作业题型 | 缺少课程题型参考 | 使用原创题并降低“贴近课程”标识 |
| 最终验证题不足 | 无法充分独立验证 | 使用迁移题并降低结论置信度 |
| 网络或生成超时 | 本次生成未完成 | 保存上下文，支持重试 |
| 资料被删除 | 相关引用或内容可能失效 | 展示影响清单后更新状态 |
| 数据访问越界 | 无权访问该课程数据 | 拒绝访问并记录异常 |

## 12. 权限与数据边界

首版即使只有一个用户，也按多用户隔离原则设计：

- 用户只能访问自己的课程；
- 课程资料不能跨课程检索，除非用户明确开启；
- 最终验证题与教学上下文隔离；
- 答案或评分规则不进入练习生成上下文；
- 删除课程时删除其派生知识地图、索引和学情；
- 用户可以查看资料用途和数据使用说明。

## 14. 产品验收场景

### 场景 A：课程初始化

用户上传一份 syllabus、多份课件和作业，完成用途确认，系统生成可修改的课程知识地图和时间线。

### 场景 B：知识点理解

用户进入一个统计学定义，查看课程原文、直觉解释、构造原因、例子、应用和标准做题步骤，并能指出具体不理解的位置。

### 场景 C：作业驱动练习

系统识别作业题对应的知识点和考法，生成多道相似但不重复的练习，用户完成后获得正确性和错因反馈。

### 场景 D：讲练切换

用户连续出现条件判断错误，AI说明原因并切换到反例讲解；表现稳定后建议进入应用题。

### 场景 E：独立验证

用户通过练习后进入无提示验证，完成未用于教学和生成的题目，系统根据证据更新掌握状态。

### 场景 F：错误与恢复

用户发现知识地图节点或AI题目错误，能够查看来源、修改或举报，并只重新处理受影响部分。

## 16. 本轮需要确认的产品决策

请在评审时重点确认以下事项：

1. **课程地图是否作为首页核心**：建议是，进入课程后首先看到课程总览和知识地图。
2. **初始化是否必须人工审核**：建议必须审核，否则错误结构会污染后续讲解和题目。
3. **是否允许用户直接标记“已掌握”**：建议不允许，只能通过验证或标记AI判断不准确。
4. **最终验证题是否完全无提示**：建议是；退出后可重学，但本次验证记为未完成。
5. **作业原题的默认用途**：建议默认“仅用于参考出题”，由用户主动选择一部分作为最终验证。
6. **AI何时插入练习**：建议AI主动推荐，但用户可继续讲解或直接开始测试。
7. **MVP是否包含基础学习顺序**：建议包含基于知识依赖的顺序，但不做日历排程。
8. **课程结构修改后的处理**：建议仅重算受影响节点，并提示相关题目和学情可能失效。
9. **资料外扩展知识**：建议允许，但必须显著标记且默认不用于正式掌握判断。
10. **首门验证课程**：需要用户选择并提供真实 syllabus、课件和作业。

## 17. 方案结论

本方案以课程知识地图为产品核心，以单知识点学习工作台为主要使用场景，以“讲解—练习—反馈—重学—最终验证”为核心闭环。

产品差异化集中在：

- 从真实课程资料重建知识体系；
- 围绕“为什么”和“如何应用”进行深度教学；
- 从真实作业学习课程考法，但不复制原题；
- 将练习数据与最终验证数据隔离；
- 让Agent主动决定教学节奏，同时保留用户控制；
- 以可见证据而不是单次正确率判断掌握。

本方案确认后，下一阶段进入 AI与技术方案设计，包括三个 POC、模型选型、RAG、文档解析、知识地图构建、题目生成与验证、评估集、兜底和成本设计。
